# Test corpus: CEN EN 16931 CII 1.3.17

Derived from the official CEN/TC 434 validation artefacts vendored in
`artefacts/cen-en16931-cii-1.3.17/` (tag `validation-1.3.17`, commit
`6e35e0ab8b09eb183f7d84b282e24ef95f9f5715`; see the README there).

## Contents

- `cases.tsv`: every upstream case: the 15 example documents of `cii/examples/` and 9 documents
  extracted from the VEFA unit test sets of `test/cii/`, with the rule ids each VEFA test
  expects. These are the test folders the upstream build runs for CII.
- `vefa/`: the extracted documents, one per `<test>`.
- `mutations.tsv` and `mutations/`: 808 mutation cases, modified copies of
  `cii/examples/CII_example5.xml`, `CII_example3.xml`, `CII_example2.xml`,
  `CII_business_example_Z.xml` and `XRechnung-O.xml`, made by the edits of
  `../mutations-cii.toml` (see `../README.md`). Each document is a modified version of its
  upstream document: the edits that modify it are those of its mutation in
  `../mutations-cii.toml`, and the history of this repository dates each modification.
- `golden/`: the expected result of each case, Saxon-HE 12.10 running
  `cii/xslt/EN16931-CII-validation.xslt`, in the canonical form described in
  `../SVRL-CANONICAL.md`; for the 54 mutation cases on which it stops with a dynamic error,
  that error (`<case id>.error.txt`).
- `vefa-disagreements.tsv`: the cases where the goldens and the VEFA expectations disagree, each
  with its explanation (none for this release).

`cases.tsv`, `vefa/`, `mutations.tsv`, `mutations/` and `LICENSE.txt` are generated by
`cargo xtask corpus --write`, the goldens by `cargo xtask oracle --write`; see `../README.md`.

## Rules the corpus exercises

The stylesheet has 810 distinct assert ids; 785 of them fail in at least one golden (21 in the
upstream cases alone). The 25 others cannot fail on any document, or only after another rule
has stopped the stylesheet:

- 6 asserts whose test is `true()`: BR-CO-05 to BR-CO-08, BR-IG-09, BR-IP-09.
- 9 asserts of rules whose context is the context of an earlier rule of the same pattern, which
  matches first: CII-DT-010 to CII-DT-012 (after `//ram:TypeCode`), CII-SR-039 to CII-SR-044
  (after the first rule on `ram:AssociatedDocumentLineDocument`).
- 2 asserts that quantify over the rate of the parent of the VAT breakdown, which has none:
  BR-IG-08 and BR-IP-08 (`every $rate in ../ram:RateApplicablePercent/...` holds on an empty
  sequence).
- 8 asserts that count elements other rules read as a single value: a second
  `LineTotalAmount`, `ChargeTotalAmount`, `AllowanceTotalAmount`, `TaxBasisTotalAmount`,
  `RoundingAmount`, `GrandTotalAmount`, `TotalPrepaidAmount` or `DuePayableAmount` makes those
  rules raise a dynamic error first (CII-SR-477 to CII-SR-482, CII-SR-484, CII-SR-487; the
  error is the golden of the mutation case).
